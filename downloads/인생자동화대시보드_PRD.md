# 인생 자동화 대시보드 목업 PRD

> PRD(Product Requirements Document, 제품 요구사항 문서)

## 1. 목적

메일, 신청 폼, 통화, 문자, 파일에서 들어온 일을 한곳에서 확인하는 `인생 자동화 대시보드`의 화면 목업을 만든다.

이번 결과물은 실제 자동화 시스템이 아니다. 책을 읽는 사람이 앞으로 만들 대시보드의 전체 모습을 먼저 보고, 자신의 일이 어떤 화면에 모일지 상상할 수 있게 만드는 것이 목적이다.

## 2. 이 목업이 필요한 이유

자동화가 돌아가도 결과가 메일함, 캘린더, 가계부, 파일 폴더에 흩어져 있으면 사람은 여러 프로그램을 다시 열어봐야 한다. 대시보드는 그 결과를 한 화면에 모으되, 모든 기록을 같은 크기로 늘어놓지 않는다.

사람이 지금 판단해야 하는 일은 위에서 바로 보이게 하고, 직접 답장할 문의와 오늘 할 일은 그다음에 둔다. 자동화가 이미 끝낸 일은 아래로 내려 결과만 확인할 수 있게 한다.

화면을 연 사용자는 다음 질문에 바로 답할 수 있어야 한다.

- 지금 내가 판단해야 할 일은 무엇인가?
- 직접 답장해야 할 문의는 무엇인가?
- 오늘 끝내야 할 일과 확정된 일정은 무엇인가?
- 자동화가 끝낸 일과 멈춘 일은 무엇인가?
- 각 항목은 어디에서 들어왔고, 왜 이렇게 분류됐는가?

## 3. 원하는 결과

완성 결과는 브라우저에서 바로 열어볼 수 있는 `index.html` 파일 하나다. 화면 안에는 교육용 가상 데이터를 넣는다.

왼쪽 메뉴를 누르면 업무를 보는 방식에 따라 화면 전체가 바뀌어야 한다. 항목을 누르면 원문, 분류 이유, 다음 행동을 볼 수 있어야 한다. 실제 메일 전송이나 일정 등록, 데이터 저장은 하지 않는다.

## 4. 사용하는 사람

코딩을 모르지만 자신의 반복 업무를 자동화하고 싶은 직장인, 프리랜서, 1인 사업자를 대상으로 한다.

사용자는 아침에 일을 시작할 때 대시보드를 열어 확인할 일과 오늘 할 일을 살펴본다. 오후에는 자동화가 처리한 결과와 남은 일을 다시 확인한다. 사용법을 따로 배우지 않아도 무엇부터 봐야 하는지 알 수 있어야 한다.

## 5. 전체 화면 구조

화면은 왼쪽 사이드바와 오른쪽 내용 영역으로 나눈다.

### 왼쪽 사이드바

사이드바 메뉴는 `보기`와 `종류별` 두 묶음으로 나눈다.

#### 보기

1. `통합 대시보드`
2. `확인필요`
3. `오늘 할 일`
4. `캘린더`

#### 종류별

5. `문의·답장`
6. `결제 기록`
7. `자동화 기록`

메뉴를 누르면 오른쪽 내용 영역 전체가 해당 화면으로 바뀐다. 현재 보고 있는 메뉴는 배경색과 글자색으로 분명하게 표시한다.

### 오른쪽 내용 영역

각 화면 상단에는 다음 내용을 표시한다.

- 화면 이름
- 이 화면에서 무엇을 볼 수 있는지 설명하는 짧은 문장
- 필요한 경우 항목 수나 상태 요약

`통합 대시보드` 상단에는 다음 내용도 함께 표시한다.

- `인생 자동화 대시보드`
- `오늘 내가 확인하고 결정할 일만 모았습니다.`
- 오늘 날짜
- 마지막 확인 시각
- `화면 목업 · 예시 데이터` 표시

## 6. 통합 대시보드

통합 대시보드는 하루를 시작할 때 가장 먼저 보는 화면이다. 사용자가 처리해야 하는 일부터 자동화가 끝낸 일까지 한 화면에서 훑어볼 수 있어야 한다.

### 상단 요약

다음 네 숫자를 카드로 보여준다.

- `확인필요`
- `수동답장처리`
- `오늘 할 일`
- `오늘 자동 처리`

요약 카드를 누르면 해당 내용을 자세히 볼 수 있는 화면으로 이동한다.

### 자료 출처 필터

다음 필터를 표시한다.

- 전체
- 메일
- 신청 폼
- 통화
- 문자
- 파일

필터를 누르면 통합 대시보드의 목록과 숫자가 해당 출처의 자료만 보여주도록 바뀐다.

### 내용 배치 순서

통합 대시보드 안에서는 다음 순서를 유지한다.

1. `확인필요`
2. `수동답장처리`
3. `오늘 할 일`
4. 확정 일정
5. 결제 기록
6. `자동답장처리`
7. 자동화 상태와 최근 기록

`확인필요`와 `수동답장처리`는 넓게 보여준다. 오늘 할 일, 일정, 결제 기록은 옆에서 빠르게 훑어볼 수 있게 정리한다. 사람이 지금 행동할 필요가 없는 `자동답장처리`와 정상 실행 기록은 아래에 접힌 형태로 둔다.

## 7. 확인필요 화면

자동화가 기준 문서에 없는 경우를 만났거나, 정보가 부족해 뜻을 정할 수 없는 항목만 모아 보여준다. 이미 처리 기준이 있는 일을 매번 승인받는 화면으로 만들지 않는다.

각 항목에는 다음 내용을 표시한다.

- 항목 제목
- 들어온 곳과 시각
- 확인이 필요한 이유
- 사람이 확인할 다음 행동
- 관련된 기록

`확인필요` 화면 상단에는 전체 건수와 출처별 건수를 간단히 보여준다.

## 8. 오늘 할 일 화면

메일과 통화에서 나온 행동을 기한순으로 보여준다. 한 통화에서 서로 다른 행동이 두 개 나왔다면 할 일도 두 줄로 나눈다.

각 항목에는 다음 내용을 표시한다.

- 할 일
- 관련된 사람이나 업무
- 기한
- 출처
- 현재 상태

오늘 마감인 일을 먼저 두고, 내일까지 해야 할 일을 그다음에 둔다.

## 9. 캘린더 화면

캘린더는 한 주의 확정 일정, 일정을 준비하기 위해 확보한 작업 시간, 아직 답장이 필요한 일정 후보를 함께 보여주는 주간 타임라인이다.

왼쪽에는 일정이나 작업 이름을 표시하고, 오른쪽에는 월요일부터 일요일까지 날짜 열을 둔다. 오늘 날짜의 열은 옅은 색 배경과 세로선으로 강조한다.

표시 방법은 다음과 같이 구분한다.

- 확정 일정: 파란색 계열의 막대
- 작업 시간: 보라색 계열의 막대
- 일정 후보: 점선 테두리 막대

`다음 주 화요일에 미팅 가능하세요?`는 확정 일정이 아니다. 그러나 사람이 할 일은 명확하므로 `확인필요`가 아니라 `수동답장처리`로 분류한다. 캘린더에는 답장 전인 `일정 후보`로만 표시한다.

## 10. 문의·답장 화면

문의는 `수동답장처리`와 `자동답장처리`로 나눠 보여준다.

### 수동답장처리

사람이 내용을 확인한 뒤 직접 보내야 하는 문의를 둔다. 접속 오류처럼 시간이 급한 문의를 가장 위에 놓는다.

각 항목에는 다음 내용을 표시한다.

- 문의 제목
- 들어온 곳과 시각
- 직접 답장해야 하는 이유
- 답장 전에 확인할 내용
- 긴급 또는 일정 후보 같은 표시

### 자동답장처리

기준이 이미 정해져 있어 자동으로 답장이 끝난 문의를 둔다. 사람이 지금 행동할 필요가 없으므로 `수동답장처리`보다 아래에 작게 보여준다.

각 항목에는 다음 내용을 표시한다.

- 문의 제목
- 들어온 곳
- 보낸 답장의 종류
- 처리 시각

자동 답장이 실패했다면 이 목록에 완료된 일처럼 남기지 않는다. 실패 이유와 함께 `확인필요`에 표시한다.

## 11. 결제 기록 화면

문자에서 확인된 지출과 아직 확인이 필요한 결제 후보를 나눠 보여준다.

확인된 결제에는 다음 내용을 표시한다.

- 금액
- 사용처
- 결제 시각
- 분류
- 기록 상태

사용처가 없거나 실제 지출인지 알 수 없는 문자는 결제 후보로 보여주고 `확인필요` 상태를 붙인다.

## 12. 자동화 기록 화면

자동화마다 현재 상태와 최근 처리 결과를 보여준다.

표시할 자동화는 다음과 같다.

- 녹음 정리
- 문자 분류
- 다운로드 정리
- 메일 답장 분류
- 캘린더 연결
- Slack 알림

각 자동화에는 다음 내용을 표시한다.

- 자동화 이름
- `정상`, `확인필요`, `멈춤`, `연결 전` 중 하나의 상태
- 마지막 실행 시각
- 마지막 처리 결과

정상 기록은 작게 보여주고, 사람이 확인해야 하는 상태는 눈에 띄게 표시한다.

## 13. 항목 상세 보기

목록에서 항목을 누르면 화면 오른쪽에서 상세 영역이 열린다. 화면이 좁을 때는 아래에서 올라오는 형태로 바꾼다.

상세 영역에는 다음 내용을 표시한다.

- 원문
- 들어온 곳과 시각
- 분류 결과
- 그렇게 분류한 이유
- 사람이 할 다음 행동
- 관련된 할 일, 일정, 결제 기록

상세 영역 바깥이나 닫기 버튼을 누르면 원래 화면으로 돌아온다.

## 14. 가상 데이터

모든 이름, 회사, 일정, 결제 정보는 교육용 가상 정보로 만든다. 실제 개인정보를 사용하지 않는다.

| 화면 | 항목 | 표시할 내용 |
|---|---|---|
| 확인필요 | `그 자료를 다음 주까지 보내주세요` | 어떤 자료를 뜻하는지 알 수 없어 통화 원문을 확인해야 함 |
| 확인필요 | `49,000원 승인` | 사용처가 없어 지출로 기록할지 판단해야 함 |
| 수동답장처리 | `오늘 수업 링크가 열리지 않아요` | 새 링크를 확인한 뒤 바로 답장해야 하는 긴급 문의 |
| 수동답장처리 | `다음 주 화요일에 미팅 가능하세요?` | 기존 일정을 확인하고 가능한 시간을 직접 답장해야 하는 일정 후보 |
| 오늘 할 일 | `수정 견적서 보내기` | 통화에서 생성된 일. 오늘 오후 5시까지 |
| 오늘 할 일 | `교육장 HDMI 어댑터 확인하기` | 통화에서 생성된 일. 내일까지 |
| 확정 일정 | `다온문화센터 AI 업무 자동화 강의` | 내일 오후 2시. 캘린더 반영 완료 |
| 작업 시간 | `세금계산서 발급` | 오늘 오전 11시 |
| 결제 기록 | `한빛문구 32,000원` | 사무용품. 지출 기록 완료 |
| 자동답장처리 | `강의 자료를 다시 받을 수 있을까요?` | 자료 링크 자동 발송 완료 |
| 자동답장처리 | `신청이 정상적으로 접수됐나요?` | 신청 완료 안내 자동 발송 |
| 자동화 기록 | 녹음 정리 | 통화에서 할 일 두 건 생성 |
| 자동화 기록 | 문자 분류 | 배송 알림 보관, 광고 문자 제외 |
| 자동화 기록 | 다운로드 정리 | 중복 파일 한 건 건너뜀 |

화면의 날짜와 요일은 브라우저를 연 날을 기준으로 자연스럽게 보이게 한다.

## 15. 화면에서 작동할 범위

이번 목업에서는 다음 동작만 만든다.

- 왼쪽 메뉴로 일곱 가지 화면 전환
- 통합 대시보드의 자료 출처 필터
- 통합 대시보드의 요약 카드에서 관련 화면으로 이동
- 항목을 눌러 상세 내용 열기와 닫기
- `자동답장처리`와 자동화 상태 영역 접기와 펼치기
- 노트북과 휴대폰 너비에 맞춘 화면 배치

버튼을 눌렀을 때 실제 메일, 캘린더, 파일, 데이터베이스에는 아무 변화도 생기지 않는다.

## 16. 화면 표현

- 일반적인 업무 도구처럼 단정하고 편안하게 보이게 한다.
- 밝은 회색 바탕 위에 흰색 카드와 짙은 색 사이드바를 사용한다.
- `확인필요`는 따뜻한 주황색 계열로 가장 눈에 띄게 한다.
- `수동답장처리`는 파란색 계열로 표시한다.
- 오늘 할 일은 보라색 계열로 표시한다.
- `자동답장처리`와 정상 상태는 채도가 낮은 초록색 계열로 표시한다.
- 색만으로 상태를 구분하지 않고 상태 이름을 함께 쓴다.
- 모든 영역을 같은 크기의 카드로 만들지 않는다.
- `확인필요`를 가장 크게 보여주고, 자동으로 끝난 결과는 작게 보여준다.
- 장식용 그래프, 거대한 숫자, 그라데이션, 홍보 문구는 넣지 않는다.
- 긴 설명보다 상태, 이유, 다음 행동이 먼저 읽히게 한다.

## 17. 화면 크기에 따른 배치

노트북 화면에서는 왼쪽 사이드바를 고정하고 오른쪽에 내용이 보이게 한다. 가로 스크롤이 생기지 않아야 한다.

화면이 좁아지면 사이드바를 상단의 가로 메뉴로 바꾸거나 접을 수 있는 메뉴로 바꾼다. 카드가 여러 열로 놓여 있었다면 한 열씩 쌓는다. 정보의 순서는 넓은 화면과 같게 유지한다.

## 18. 제작 조건

- 결과물은 `index.html` 파일 하나로 만든다.
- CSS와 JavaScript는 같은 파일 안에 넣는다.
- 외부 라이브러리, 외부 폰트, 외부 이미지에 의존하지 않는다.
- 서버 실행이나 계정 로그인 없이 파일을 브라우저에서 열 수 있어야 한다.
- 인터넷에 연결하지 않아도 화면과 동작이 깨지지 않아야 한다.
- 모든 문구는 한국어로 쓴다.
- 상태 이름은 `확인필요`, `수동답장처리`, `자동답장처리`로 띄어쓰기 없이 통일한다.
- 폴더 이름과 파일 이름에는 공백을 넣지 않는다.
- 이 PRD 파일은 수정하지 않는다.

## 19. 이번 목업에서 만들지 않을 것

- 항목 추가, 수정, 삭제
- 완료 상태와 메모 저장
- 새로고침 뒤에도 데이터가 남는 기능
- 실제 메일, 신청 폼, 통화, 문자, 파일 연결
- 실제 답장 발송
- AI 호출과 문장 의미 판단
- 데이터베이스
- 캘린더와 Slack 전송
- 로그인과 사용자 계정
- 인터넷 배포
- Next.js 변환

## 20. 완료 기준

- `index.html`을 브라우저에서 바로 열 수 있다.
- 상단에 `화면 목업 · 예시 데이터`가 표시된다.
- 왼쪽 메뉴에서 일곱 가지 화면을 오갈 수 있다.
- `통합 대시보드`와 나머지 화면이 서로 다른 내용으로 전환된다.
- `확인필요`가 통합 대시보드에서 가장 먼저 눈에 들어온다.
- `수동답장처리`와 `자동답장처리`가 분명하게 나뉜다.
- 접속 오류 문의가 `수동답장처리`의 가장 위에 보인다.
- 미팅 가능 여부 문의가 `수동답장처리`와 캘린더의 `일정 후보`에 표시된다.
- 자동으로 끝난 답장과 정상 실행 기록은 통합 대시보드 아래에 있다.
- 캘린더 화면에서 한 주의 확정 일정, 작업 시간, 일정 후보를 구분할 수 있다.
- 결제 기록에서 완료된 지출과 확인이 필요한 결제 후보를 구분할 수 있다.
- 항목을 누르면 원문, 분류 이유, 다음 행동이 열린다.
- 통합 대시보드에서 출처를 선택하면 목록과 숫자가 함께 바뀐다.
- 노트북 화면에서 가로 스크롤이 생기지 않는다.
- 휴대폰 화면에서도 정보 순서가 유지된다.
- 실제 개인정보를 사용하지 않는다.
- 실제 답장 발송, 외부 서비스 연결, 데이터 저장은 일어나지 않는다.
